# Задание 2. Подготовка базы знаний

## 1. Выбранная предметная область

В качестве исходного мира выбрана Terraria. Источником служит локальный MediaWiki XML-дамп `terraria_gamepedia_pages_current.xml`, поэтому генерация базы не зависит от доступности сайта и не требует сетевых запросов.

В базу включены 36 сущностей:

- 18 противников-боссов;
- 18 дружественных NPC.

Исходные статьи не копируются в базу целиком. Для каждой сущности сохраняется вводное описание и только содержательные разделы: способы появления, поведение, последствия победы либо условия появления и предпочтения NPC. История правок, платформенные примечания, шаблоны, ссылки на изображения и служебная wiki-разметка удаляются.

## 2. Вымышленный мир

Преобразованная вселенная называется **Aetherfall**. В ней боссы представлены как `sovereign`, а мирные NPC — как `settler`. Например:

| Исходный термин | Термин в Aetherfall |
| --- | --- |
| Eye of Cthulhu | Watcher of the Rift |
| Wall of Flesh | Gatekeeper Mass |
| Moon Lord | Sovereign of the Pale Orbit |
| Guide | Pathkeeper |
| Dryad | Verdant Oracle |
| Hardmode | Ascendant Era |
| The Corruption | Umbral Blight |
| Dungeon | Vault of Echoes |
| Blood Moon | Scarlet Eclipse |

Полный словарь находится в [`terms_map.json`](terms_map.json). Это исходный файл конфигурации для подмены, а не результат работы генератора. Ключ каждого JSON-поля — термин из Terraria, значение — его вымышленный аналог в Aetherfall. В словарь входят имена всех 36 сущностей, регионы, эпохи, события, режимы, предметы призыва и некоторые характерные предметы и атаки.

При необходимости название можно изменить непосредственно в `terms_map.json`. При следующем запуске скрипт прочитает новое значение и применит его к содержимому, заголовку и имени файла соответствующей сущности. Формат словаря строго проверяется: ключи и значения должны быть непустыми строками, а для каждой из 36 выбранных страниц должна существовать замена.

Цель подмены — не скрыть литературный источник от человеческого анализа, а исключить ответ по точным сущностям из памяти модели. Модель может заметить сходство отдельных механик с известной игрой, однако соответствия `Watcher of the Rift`, `Pathkeeper` или `Ascendant Era` без созданной базы ей неизвестны. Это позволяет проверить, действительно ли ответ опирается на retrieval.

## 3. Автоматическая обработка

Скрипт [`build_knowledge_base.py`](build_knowledge_base.py) выполняет следующие действия:

1. Потоково читает XML через `iterparse`, не загружая дамп размером более 100 МБ целиком в память.
2. Выбирает только статьи из основного пространства имён и только 36 заданных страниц.
3. Разбирает wikitext, удаляет шаблоны, сноски, изображения и неиспользуемые разделы.
4. Удаляет строки, испорченные платформенными и версионными шаблонами.
5. Читает и валидирует `terms_map.json`, после чего выполняет регистронезависимую замену терминов за один проход. Более длинные выражения обрабатываются раньше коротких, поэтому `Eye of Cthulhu` не превращается в частично заменённую строку, а результаты замен не заменяются повторно.
6. Проверяет число документов, уникальность имён, минимальную длину, отсутствие MediaWiki-разметки и всех исходных терминов.
7. Пересоздаёт только Markdown-файлы в детерминированном порядке; исходный `terms_map.json` не изменяет.

Перечень 36 исходных страниц и их категории задан непосредственно в скрипте. Все пары «исходный термин → вымышленный термин» хранятся только в `terms_map.json`, а ключевые операции покрыты тестами в [`tests/test_build_knowledge_base.py`](tests/test_build_knowledge_base.py).

Запуск из корня репозитория:

```bash
venv/bin/pip install -r Task2/requirements.txt
venv/bin/python -m Task2.build_knowledge_base
```

Альтернативный запуск с `uv`:

```bash
uv run --with mwparserfromhell==0.7.2 --with pydantic==2.12.5 python -m Task2.build_knowledge_base
```

## 4. Результат

Каталог [`knowledge_base/`](knowledge_base/) содержит 36 Markdown-документов — по одному на сущность. Каждый файл имеет YAML-метаданные, заголовок и очищенный текст:

```yaml
---
entity: Watcher of the Rift
category: sovereign
world: Aetherfall
---
```

Такая структура подходит для последующей нарезки на чанки и позволяет сохранить в метаданных имя сущности, тип документа и название мира.

Для проверки RAG следует составлять вопросы только с вымышленными терминами, например:

- При каких условиях появляется Watcher of the Rift?
- Что меняется после победы над Gatekeeper Mass?
- Как получить Gearling Artificer?
- Какие услуги оказывает Pathkeeper?

До индексации локальная или облачная LLM не должна знать ответы на такие формулировки. После индексации ответы должны подтверждаться найденными фрагментами из `knowledge_base/`.
